# Grill Me：把想法问透

基于 Matt Pocock 的 grill-me / grilling，适配 Codex。默认中文，跟随用户指定语言。目标是共同澄清想法，不是替用户做决定或立即实施。

## 分轮追问

- 从用户已有信息建立内在“决策树”：目标和边界在上游，方案、异常、验收等决定依赖它们。没有主题时只先问用户要讨论什么。
- 每轮找出所有前置条件已明确的未决问题，只问当前可回答的问题。依赖本轮另一个答案的问题放到下一轮，不预设用户选择。
- 每个问题编号，解释关键取舍，并给出推荐答案及简短理由；明确推荐是建议而非既定结论。信息不足时给条件式建议，不伪造确定性。
- 默认同轮提出当前可回答的独立问题；用户要求一次一个、限制数量或缩小范围时遵从。每轮以问题结束并等待回答，不模拟用户回答，不在同一轮继续推进。
- 用户答复后更新树，保留已确认决定；只对新出现的矛盾或依赖变化重新追问。发现隐含假设、失败场景或不可逆决定时直截了当地指出问题，避免对人评判。

示例格式：

**Q1 · 目标**：首先要解决谁的什么问题？什么结果算成功？

建议：先选一个主要使用者和可观察的成功标准，因为它们决定后续范围。

**Q2 · 边界**：这一轮明确不做哪些事情？

建议：列出最容易被顺带加入的范围，避免方案越讨论越大。

示例不是每轮固定必问模板。只提当前主题真正需要回答的问题。

## 事实与决策分开

环境、代码、文档中可查的事实由 Codex 做相关只读检查，不让用户代查；说明证据与不确定性。无法访问时说明具体缺口，不猜测。用户偏好、预算、取舍等决策仍由用户确认。

不依赖 Claude 的 Skill/AskUserQuestion 工具或其他插件。普通聊天即可完成问答，当前模式提供合适的提问工具时可以使用。不要为此强制切换 Plan 模式。事实检索默认由当前 Codex 完成；只有用户或上层规则另行允许时才委派子代理，本技能不要求额外代理。

对必须通过原型、实验或真实数据才能判断的问题，明确标记“需要验证”，建议最小实验并等待用户授权；不要用更多追问代替证据，也不要自动创建原型。

## 收束与边界

本技能默认无状态：只在当前对话维护决定，不写文件、不改代码、不创建工单、不上传材料。

当约定范围内没有新的可回答未决分支时，用简短汇总列出已确认决定、关键取舍、仍待验证/主动推迟的事项，请用户确认共同理解。不要声称未知事项已解决。用户要求停止或先汇总时立即收束，不以“必须问完”为由继续。

确认理解不等于授权实施。只有用户明确要求实现、保存文档或执行实验时，才进入对应的另一个任务范围。

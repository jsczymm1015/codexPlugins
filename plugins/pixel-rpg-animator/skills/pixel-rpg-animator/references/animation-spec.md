# 逐帧动作规范

## 固定画布

生成前选定相同单元格、角色缩放、水平锚点和地面基准线，为手脚留足空间。优先横向1行8列，不强制正方形，不压扁角色凑比例。可把128×192像素单元格、1024×192单行画布作为请求起点；工具支持的分辨率优先，实际输出必须测量，不能保证请求尺寸一定兑现。总图集的每格大小必须与通过检查的单行一致。

允许自然的小幅上下起伏和抬脚离地；禁止单元格内整体横向漂移。不要逐帧裁紧再分别缩放，不为对齐拉长腿。若统一调整画布或缩放，所有帧采用同一规则，像素缩放用最近邻。

## 行走：1行8列，10 FPS，循环

按时间从左到右。左右均指角色自身的左右。

1. 左脚前伸接触地面，右脚在后。
2. 重心落到左脚，身体轻微下沉。
3. 右脚经过支撑腿，双腿接近。
4. 右脚向前摆出，左脚在后支撑。
5. 右脚前伸接触地面，左脚在后。
6. 重心落到右脚，身体轻微下沉。
7. 左脚经过支撑腿，双腿接近。
8. 左脚向前摆出，自然衔接第1帧。

朝下、朝上保持同一接触/承重/经过/摆出节奏，按相应视角展示。手臂与对侧腿协调小幅摆动，头部稳定、肩膀放松、衣摆轻微跟随。禁止变成奔跑、大幅挥手、突然抬臂或异常高抬膝。第8帧不是复制第1帧。

## 扩展动作：仅用户请求时

例图视觉上是6行8列，包含正面待机/小动作、右向行走、右向奔跑、上肢攻击、踢击/战斗姿态、受击倒地；它的重复站姿和不连续动作不能当作规范逐帧周期。

用户要求按例图完整制作时，默认6行8列：idle_front、walk_right、run_right、punch_front、kick_front、hurt_fall。先基准，再逐行动作，最后合成；不与4方向行走图集混为一张。用户可指定更多方向或改动作列表。

- 待机：呼吸和轻微衣物变化，循环。不要随机插入攻击手势。
- 奔跑：明确腾空与交替支撑，循环；与行走分开。
- 出拳、踢击：准备→蓄力→发力→接触→回收→恢复，动作有清晰时间顺序；默认不循环，8帧分配给完整动作，不凑8个任意姿势。
- 受击倒地：受击→失衡→下落→触地→稳定卧倒，默认不循环，末帧保持；不要把尸体姿势强行接回站立。

8帧与10 FPS只是起点，攻击节奏或倒地时长可按用户需求调整并在交付说明里标注。

## 检查清单

1. 确认每行8格，每格完整可见，手脚不跨格、不触边裁断；图片没有文字、帧号、网格、地面装饰。
2. 对照基准看脸型、头发、胡须、腰带、纹样、服装色及身材是否一致。检查肢体增减、粘连、轮廓闪变、颜色跳变。
3. 检查固定地面基线和身体中心，区分自然身体起伏与整个人物漂移。
4. 逐帧看支撑脚与摆动脚是否交替，手臂是否与对侧腿配合；侧面全站姿重复不算行走。
5. 比较相邻帧，包括循环动作8→1；非循环倒地不要按首尾衔接判失败。
6. 如可读取像素，核查 PNG 格式及 alpha 中是否实际存在透明像素；仅有 RGBA 通道不等于透明背景。JPG不是透明图，棋盘格像素不是透明。
7. 记录真实尺寸及宽度/8、总图高度/4或/6的整除情况。尺寸正确不代表姿势连续。未运行游戏时不要声称游戏验证通过。

## 提示词组织

生成时把“本次角色已锁定特征 + 实际参考图 + 本次唯一动作与方向 + 帧序 + 固定画布/锚点 + 风格/背景 + 禁止项”组成简洁提示词。不要将不同阶段的所有动作同时交给图像模型，也不要只写“根据上图做动作”而省略时序。
